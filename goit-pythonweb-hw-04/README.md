# Тема 4. Асинхронне програмування. Домашнє завдання

## Реалізовано

- Асинхронний ітеративний обхід файлів із вихідної папки (без ризику переповнення стеку)
- Обмеження кількості in-flight задач копіювання для стабільнішого споживання пам'яті
- Асинхронне копіювання файлів у цільову папку
- Опційний режим переміщення: після успішного перенесення файл видаляється з `SOURCE_FOLDER`
- Опційне очищення порожніх директорій у `SOURCE_FOLDER` після перенесення
- Сортування файлів по підпапках за розширенням (`txt`, `jpg`, `py` тощо)
- Файли без розширення потрапляють у папку `no_extension`
- Дедуплікація за SHA-256 у межах типу навіть при різних назвах файлів:
  - однаковий вміст -> дублікат пропускається
  - різний вміст при колізії імені -> створюється нове ім'я з суфіксом (`_1`, `_2`, ...)
- Кеш-індекс хешів у межах цільової папки типу для прискорення дедуплікації
- Логування ключових подій та помилок

## SOLID-орієнтована архітектура

- SRP: обов'язки розділено між оркестратором сортування та окремими стратегіями
- OCP: правила сортування і дедуплікації можна змінювати новими реалізаціями без зміни ядра
- DIP: оркестратор працює через абстракції (`Protocol`) для резолвера розширень, хешування, колізій і копіювання
- ISP: невеликі інтерфейси з мінімальними контрактами
- LSP: будь-яка реалізація стратегії може бути підставлена замість стандартної

## Структура модулів

```text
goit-pythonweb-hw-04/
  main.py
  sorter/
    cli.py
    service.py
    maintenance.py
    strategies.py
    protocols.py
    models.py
```

- main.py: тонкий entrypoint для запуску
- sorter/cli.py: парсер аргументів, валідація шляхів, запуск workflow
- sorter/service.py: оркестратор асинхронного обходу та копіювання
- sorter/maintenance.py: сервіси видалення source-файлів і очищення порожніх директорій
- sorter/strategies.py: стратегії розширень, хешування, колізій і копіювання
- sorter/protocols.py: контракти для інверсії залежностей
- sorter/models.py: моделі статистики і рішення по destination

## Запуск

1. Встановіть залежності:

```bash
pip install -r requirements.txt
```

2. Запустіть скрипт:

```bash
python main.py SOURCE_FOLDER OUTPUT_FOLDER
```

Приклад:

```bash
python main.py ./source ./output --workers 10
```

Приклад сортування тільки обраних типів:

```bash
python main.py ./source ./output --types jpg png jpeg
```

Приклад сортування з виключенням типів:

```bash
python main.py ./source ./output --exclude-types tmp db no_extension
```

Приклад іменування файлів за хешем (в межах папки типу):

```bash
python main.py ./source ./output --name-by-hash
```

Приклад режиму переміщення (копіювання + видалення з source):

```bash
python main.py ./source ./output --move-files
```

Приклад режиму переміщення з очищенням порожніх папок source:

```bash
python main.py ./source ./output --move-files --cleanup-empty-dirs
```

Приклад з генерацією текстового звіту:

```bash
python main.py ./source ./output --workers 10 --report-file ./sort_report.txt
```

Якщо викликати без значення, звіт збережеться у `OUTPUT_FOLDER/sort_report.txt`:

```bash
python main.py ./source ./output --workers 10 --report-file
```

Також можна передати:

- шлях до файлу (кастомне ім'я і місце)
- шлях до вже існуючої папки (файл буде `sort_report.txt` у цій папці)

## Аргументи CLI

- `source` - вихідна папка для сканування
- `output` - цільова папка для відсортованих файлів
- `--workers` - кількість одночасних задач копіювання (за замовчуванням `10`)
- `--types` - опційний список типів для сортування (наприклад: `txt jpg png`), інші типи ігноруються
- `--exclude-types` - опційний список типів, які треба виключити з обробки
- `--name-by-hash` - опційний режим: файл у папці типу зберігається з іменем на основі SHA-256
- `--move-files` - опційний режим: після успішного копіювання або дедуплікації файл видаляється з `source`
- `--cleanup-empty-dirs` - опційно видаляє порожні директорії у `source` після проходу (зазвичай разом із `--move-files`)
- `--report-file` - опційний звіт. Без значення: `OUTPUT_FOLDER/sort_report.txt`; зі значенням: вказаний шлях до файлу/папки
